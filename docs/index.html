color-terminal

A new colour theme in every shell you open — applied live, to the window you are already typing in. How to make it stop.

What it does

Every time you open a shell, color-terminal picks a theme at random and applies it to the terminal that shell is running in — immediately, with no restart and no config reload.

It ships its own theme corpus in a plain text format, so it does not depend on any one terminal's theme directory. Anything that understands OSC colour sequences is supported.

It keeps the splashboard splash palette in step with the pick, so the splash never clashes with the terminal it draws into.

Nothing is printed to stdout. Ever. See how it works for why that matters. 

curl -fsSL https://lariocpt.github.io/color-terminal/install.sh | sh

Making it stop

A tool that recolours your terminal without being asked owes you a brake. There are five, from “not right now” to “gone”.

NO_COLOR=1
The no-color.org convention, honoured: if it is set to anything at all, color-terminal does nothing and exits 0.
COLOR_TERMINAL=0
Per-shell, per-session off switch — export it in one shell to mute just that shell, or in your rc file to mute the machine.
~/.config/color-terminal/hosts/<hostname>
Pin one host to one theme forever: write a theme id into that file and that host stops rolling the dice, on every shell, including over ssh.
trigger = manual
Keep it installed but never automatic: colours change only when you run color-terminal yourself.
color-terminal --uninstall
Full removal. Takes out the shell hooks, the include line it added to your terminal’s config, and the binary. Your own theme = line was never touched, so there is nothing to put back.

How it works

The whole mechanism is one kind of escape sequence, OSC — “operating system command”. You write the bytes to your terminal, and the terminal interprets them as instructions about itself rather than as text to draw: 

printf '\033]4;1;#f38ba8\033\\' > /dev/tty   # set ANSI colour 1
printf '\033]11;#1e1e2e\033\\'  > /dev/tty   # set the background

There is no API here, and nothing to install on the terminal side. Colour N in a theme file is the OSC 4 palette index verbatim, so applying a theme is a loop over sixteen of these plus one each for background and foreground.

The interesting part is where those bytes go. They travel down the pty — so when the shell is a remote one, the script running on the far host recolours the window on your desk. ssh into a box that has color-terminal installed and your local terminal changes colour, with nothing installed locally at all.

That is also why the escapes are written to /dev/tty and never to stdout. A stray escape byte on stdout corrupts anything that treats the stream as data — scp, rsync and git over ssh all break, loudly and confusingly, if a login shell prints so much as one byte of it. /dev/tty reaches the terminal while leaving the pipe clean.

When the colours change

Set trigger in ~/.config/color-terminal/config.

valuewhat fires a new colour
pane (default) the first shell in each new pane or window
shell every interactive shell
manual only when you run color-terminal yourself

pane is the default because it is the only one that matches what you actually mean by “a terminal”. A shell cannot see its window, but it can see its session: every nested shell in one pane shares a session id, and a new pane gets a new one. Without that, su, :!sh from vim, poetry shell and every coding-agent subshell would re-randomise the window while you are typing in it.

Which terminals

There are three tiers, and the third one is a feature rather than a gap.

tierwhat happenswhich
1 live recolour, plus a palette file so new windows keep the theme ghostty, foot
2 live recolour, no config written — one shared backend, no per-terminal code kitty, alacritty, wezterm, xterm, urxvt, st, rio, contour, iTerm2, Windows Terminal, VS Code, the whole VTE family — and any terminal we have never heard of, and any ssh session
3 detected, declined, and told why konsole, Warp, mosh, Apple Terminal

Tier 2 is the point: unknown is a supported case, not an error. The sequences it uses are implemented by every terminal in both tiers, so nothing has to be probed or negotiated first.

Tier 3 is declined on purpose, because emitting into those is worse than doing nothing — it looks like it worked. konsole parses the palette sequence, stores it, answers queries about it, and never renders with it; Warp ignores it; mosh drops it; Apple Terminal has no palette sequence at all. Run color-terminal --doctor to see which one you are in.

The corpus

24 themes ship with the tool — 16 dark, 8 light. Every one of them clears a contrast gate enforced at build time, so a random pick can never hand you an unreadable terminal. Drop your own into ~/.config/color-terminal/themes/; that directory is searched first and an upgrade never touches it.
